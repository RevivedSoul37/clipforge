Long video in → post-ready vertical clips out

An auto-clipper that cuts interviews the way an editor would.

ClipForge transcribes a long-form video, finds the moments worth posting, and renders finished 9:16 clips — hook, captions, music and b-roll included — with every stage running locally: faster-whisper, Ollama, ffmpeg. No cloud, no API bill.

01

How one video becomes clips

source → highlights → review → export

The default flow runs highlight selection over email instead of the local model: the transcript goes out, an AI replies with a JSON pick-list, and the reply is ingested automatically. Switch any campaign to local Ollama highlighting in Settings.

  1. Upload the source

    Drop a long-form interview into a campaign via the web UI (or the input/ folder). Each campaign is a self-contained bay with its own inputs, transcripts, candidates and outputs.

    videoserver.py api_upload · src/campaigns.py

  2. Transcribe & clean

    faster-whisper with a pinned language and a vocabulary-biasing prompt (“gym”, “discipline”, “alhamdulillah”…) cuts mishearings. A second LLM pass fixes low-confidence words using Whisper’s per-word probabilities.

    whispersrc/transcribe.py · src/clean_transcript.py · silero-vad silence trim on cuts

  3. Highlights by email

    The numbered transcript is emailed to the configured address. The AI replies with a JSON object — segment ids, hooks, scores, reasons (the contract sits at the top of the email). A background IMAP poller ingests the reply and turns it into candidates; only mail from the configured sender is trusted.

    smtp / imapsrc/email_transcript.py · src/email_highlights.py · server inbox poller every 30s

  4. Review & approve

    The Approval page shows each candidate with a preview: approve, reject, edit hook text or timing. While the reply is in flight, a waiting card holds the slot; when highlights land, the bell and Telegram both fire.

    webweb/app.js · review candidates → approved

  5. Cut, render, finish

    ffmpeg cuts each approved range with lead-in/out padding, then the template applies hook title, keyword-highlighted captions, CTA, background music and emotion-matched b-roll cutaways. Exports land in the campaign’s output/; Style Explorer winners are used automatically.

    ffmpegsrc/cut_clips.py · src/apply_template.py

03

Style System

templates · Style Lab · Style Explorer
cli + web

Templates

json render recipes

House styles like square_captioned and full_screen: band geometry, fonts, caption style, hook placement, CTA block, music and b-roll mode, color grade and vignette. Export with --template name.

cli

Style Lab

clone a style from references

frames extracts stills (uniform or scene-change sampling, contact sheets), style runs pixel analysis over them and drafts a template: band geometry, hook/caption/CTA colors, keyword highlight detection.

cli + web

Style Explorer

auto-judge with a vision llm

Generates N seeded style variants on the best clip (crop, fonts, captions, grade, music…), renders low-res previews, scores them with qwen2.5vl on legibility/contrast/style/brief-fit, and saves the winner — used automatically on the next export.

04

Notifications

web bell · desktop · telegram

Every meaningful event is published once on the internal bus and fanned out: the web bell collects it (with desktop notifications), and Telegram mirrors it to your chat over the Bot API via plain urllib — a daemon thread, a bounded queue, zero blocking, zero new dependencies. Secrets live only in .env.

Setup

three commands

telegram-setup lists recent chats with their chat id after you message the bot; paste it into TELEGRAM_CHAT_ID. telegram-test confirms delivery. Master toggle: telegram.enabled in config.json.

Delivery guarantees

never breaks the bus

Non-blocking queue + daemon worker. Missing token/chat id degrades to one warning, never a crash. Send failures swallowed with a single log line. All user text HTML-escaped; the token never appears in logs, API responses or the UI.

06

Architecture

starlette backend · one event bus · module per stage

Runs are subprocesses (main.py --emit-progress): the server streams their stdout, parses @@PROGRESS@@ lines for the progress bar and republishes @@EVENT@@ lines onto the bus. The bus feeds /api/events (long-poll) → bell, and the Telegram sink. Lifecycle events live server-side; outcome events with richer data come from the CLI and are republished — one notification per outcome, never both.

  • main.pyCLI orchestrator — all pipeline commands
  • server.pyStarlette backend — runs, API, event bus, inbox poller
  • src/config.pyconfig.json + .env → one typed config object
  • src/transcribe.pyfaster-whisper + VAD-assisted boundaries
  • src/clean_transcript.pyLLM fix of low-confidence words
  • src/select_highlights.pyOllama highlight scoring + rules
  • src/email_transcript.py / email_highlights.pySMTP out, IMAP ingest
  • src/cut_clips.pyffmpeg cutting with silence-aware padding
  • src/apply_template.pyASS captions, hook, music, b-roll graph
  • src/style_explorer.pyvariant generation + vision judging
  • src/notify.pyTelegram sink — queue, daemon thread, formatters
  • src/campaigns.pymulti-show campaign folders
07

Design rules the system enforces

Local-only

Whisper, Ollama and ffmpeg on your machine. The only network calls are SMTP/IMAP, stock b-roll APIs (optional) and Telegram.

Non-blocking notifications

The event bus never waits on Telegram; delivery rides a bounded queue and one daemon thread.

Secrets in .env only

Tokens and chat ids are gitignored, never logged, never rendered, never returned by any API.

One notification per outcome

Server emits lifecycle events; the CLI emits richer outcome events — never duplicates.

Graceful degradation

Missing config → one warning. Failed send → one log line. Everything else keeps running.

Determinism

Style variants are seeded per video; the same input gives the same explorations.
