Five steps. Read like the chat it becomes.

Steps 1 and 3 happen inside Telegram, the rest in your ClipForge folder. Your bot token and chat ID live only in .env — already gitignored.

01

Create the bot with @BotFather in Telegram

you → @BotFather

Search for @BotFather (the one with the blue verification check) and send:

/newbot

It asks for two things — a display name, e.g. ClipForge Alerts, and a username that must end in bot, e.g. clipforge_alerts_bot.

@BotFather → you

Done! It replies with your HTTP API token. It looks like this:

7123456789:AAH4k3uZ9pQwRtYx0vNb2mKj8sDfGhJkLmN

Copy it. You'll paste it into .env in the next step.

Anyone with the token controls your bot. Never paste it into the repo, the web UI, or a shared doc.
02

Put the token in .env in ClipForge

clipforge/.env

Add these two lines to the .env file in your ClipForge folder (create it from .env.example if missing):

TELEGRAM_BOT_TOKEN=7123456789:AAH4k3...
TELEGRAM_CHAT_ID=

Leave the chat ID empty for now — step 3 finds it.

03

Say hi to your bot, then read its chat ID both

you → your new bot

Open the bot by its username and send it any message (e.g. “start”). Telegram bots can't message you until you do this first.

terminal

Back in your ClipForge folder, run:

$ python main.py telegram-setup

It lists every chat that has messaged the bot — with the chat ID next to each. Fill TELEGRAM_CHAT_ID in .env with yours.

Groups and channels work too: the bot must be a member, and their IDs are negative numbers (e.g. -1001234567890).

04

Fire a test message terminal

terminal

$ python main.py telegram-test

A test notification lands in your chat within a second or two. The command also prints the raw Telegram API answer if anything is off.

05

Restart the server — events flow done

terminal

$ python server.py

That's it. Config is read at startup, so restart once after editing .env. To switch notifications off without losing the config, set "telegram": {"enabled": false} in config.json.

When nothing lands in the chat

The four things that actually go wrong, in order of likelihood.

telegram-setup shows an empty list

You haven't messaged your bot yet. Open it by username, send any message, then run the command again.

401 Unauthorized

The token in .env is wrong, or was revoked. Check it against BotFather's reply, or send /revoke to @BotFather for a fresh one.

Nothing arrives, no errors logged

Config loads at startup — restart python server.py after editing .env. Also confirm "telegram": {"enabled": true} in config.json.

Group chat gets nothing

Add the bot to the group first — Telegram blocks messages to chats it isn't a member of. Use the group's negative chat ID.
